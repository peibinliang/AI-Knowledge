# 一、中国 AI / 大模型 / 智能体：本期最值得关注的 10 条

## 1. DeepSeek 正式发布 V4 Pro：Agent 能力提升，同时旗舰模型明显提价

**发生了什么**  
8 月 13 日，DeepSeek 正式发布 V4-Pro-0813，并表示其 Agent 能力得到明显增强，已在 API、App 和 Web 端提供。根据 Reuters 引用的 Artificial Analysis 数据，V4 Pro 输入价格约为 1.32 美元/百万 Token、输出约 3.96 美元/百万 Token，分别约为 V4 Flash 的 9 倍和 14 倍；DeepSeek 还计划引入峰谷定价。

**为什么重要**  
DeepSeek 正从“极致低价”转向更清晰的模型分层：Flash 承担高频低成本任务，Pro 承担复杂推理、工具调用和 Agent 工作流。国内模型市场开始出现与全球厂商类似的旗舰模型溢价。

**对企业技术团队的影响**  
不要再默认“DeepSeek = 最低成本”。建议用内部 Coding、RAG、工具调用和长任务评测集比较 V4 Pro / V4 Flash 的**每成功任务成本**，再决定路由策略。

来源：[Reuters，2026-08-13](https://www.reuters.com/world/china/deepseek-releases-official-v4-pro-model-it-steps-up-expansion-2026-08-13/)

## 2. 智谱 GLM-5.3 把开放模型推进到网络安全高风险能力区

**发生了什么**  
8 月 14 日，Z.ai（智谱）公布 GLM-5.3 的网络安全评测结果。公司称其在 CyberGym 漏洞识别测试中达到 84.5%，接近或略高于 Anthropic 受限访问模型 Mythos 5 的公开对比结果，但在漏洞利用能力上仍明显落后。Z.ai 表示将在完成安全评估后约两周公开模型，并计划对敏感能力采用 trusted access。

**为什么重要**  
这不是普通 Benchmark 升级，而是开放权重模型开始进入“发现漏洞、自动化安全研究”等双用途能力区。开放模型的安全治理正在从内容安全扩展到工具权限、身份和使用者准入。

**对企业技术团队的影响**  
安全团队值得关注其代码审计能力，但生产使用必须配套沙箱、只读代码权限、网络隔离、审批与审计，不能把高能力安全 Agent 直接接入生产网络。

来源：[Reuters，2026-08-14](https://www.reuters.com/technology/chinas-zai-says-new-model-nears-anthropics-mythos-5-cyber-defence-tests-2026-08-14/)

# 五、GitHub AI 项目推荐

> Star 为本次执行时的快照，随时会变化。优先考虑近期仍有提交、技术方向有代表性且可用于企业研发的项目。

## 1. stablyai/orca — 多 Coding Agent 并行调度工作台

- GitHub：https://github.com/stablyai/orca
- 当前约 **4.7 万 Star**，8 月 17 日仍有代码推送。
- **做什么：** 面向 Claude Code、Codex、Cursor Agent、OpenCode 等 Coding Agent 的并行 Agent Development Environment，强调 Worktree 和多 Agent 并发。
- **为什么推荐：** AI Coding 下一阶段不是“单个 Agent 更强”，而是如何同时管理多个任务、隔离工作区、合并结果。
- **适合：** 已大量使用 Codex / Claude Code，希望探索多 Agent 软件研发流水线的团队。

## 2. affaan-m/ECC — Agent Harness / Skills / Memory 工程化方法集合

- GitHub：https://github.com/affaan-m/ECC
- 当前约 **24 万 Star**，8 月 17 日仍有代码推送。
- **做什么：** 为 Claude Code、Codex、OpenCode、Cursor 等提供 Skills、Memory、安全、研究优先开发和 Agent Harness 实践。
- **为什么推荐：** 它关注的不是模型本身，而是如何通过上下文、技能、记忆和流程提高 Coding Agent 的稳定产出。
- **适合：** 正在建立团队级 `AGENTS.md`、Skills、Prompt / Context Engineering 规范的研发组织。

## 3. agentscope-ai/QwenPaw — 可自托管的个人 / 企业入口型 AI Assistant

- GitHub：https://github.com/agentscope-ai/QwenPaw
- 当前约 **3.4 万 Star**，8 月 17 日仍有代码推送。
- **做什么：** 本地或云端部署个人 AI Assistant，支持多个聊天应用，并提供 MCP、Skills、Agent Harness 扩展能力。
- **为什么推荐：** 很适合作为“统一聊天入口 + 企业工具接入 + 私有模型”的参考实现。
- **适合：** 想做企业内部 AI 助手、消息机器人、个人 Agent 的团队。

## 4. Panniantong/Agent-Reach — 给 Agent 增加互联网检索与内容读取能力

- GitHub：https://github.com/Panniantong/Agent-Reach
- 当前约 **7.2 万 Star**，最近一周仍有代码更新。
- **做什么：** 让 Agent 通过统一 CLI 读取 / 搜索 Twitter、Reddit、YouTube、GitHub、Bilibili、小红书等内容。
- **为什么推荐：** Agent 的实际价值高度依赖 Tool Coverage。这个项目体现了“把互联网信息源做成 Agent 工具层”的方向。
- **适合：** 舆情、研究、资讯聚合、市场分析类 Agent。

## 5. huggingface/speech-to-speech — 本地开源 Voice Agent 参考栈

- GitHub：https://github.com/huggingface/speech-to-speech
- 当前约 **1.26 万 Star**，8 月 17 日仍有代码推送。
- **做什么：** 使用开源模型构建本地 speech-to-speech / Voice Agent。
- **为什么推荐：** 语音 Agent 逐渐从 ASR → LLM → TTS 的简单串联走向低延迟实时交互，本地部署又能解决隐私与成本问题。
- **适合：** 智能客服、语音助手、会议终端、离线语音应用。

## 6. llm-d/llm-d — Kubernetes 上的分布式 LLM 推理基础设施

- GitHub：https://github.com/llm-d/llm-d
- 当前约 **4000 Star**，8 月 17 日仍有代码推送。
- **做什么：** 面向现代加速器和 Kubernetes 的分布式 LLM Inference，强调智能路由与高性能推理。
- **为什么推荐：** 如果企业开始自建多模型推理平台，调度、KV Cache、路由、GPU 利用率会比“把 vLLM 跑起来”更难。
- **适合：** AI 平台团队、私有化大模型平台、GPU 集群和推理基础设施团队。

# 今日最值得行动或持续观察的 5 点

1. **【立即验证】DeepSeek V4 Pro 做内部 Agent / Coding A/B Test。** 不比较单纯 Benchmark，而比较成功率、平均执行轮次、Token、延迟与每成功任务成本。
2. **【立即补治理】把 open-weight License Review 纳入模型准入流程。** Qwen / Kimi 等商业条款变化说明“可下载”并不等于“无限制商用”。
3. **【架构评估】开始建设 Model Gateway + Evaluation + Routing。** 国内外模型迭代速度已经高到不适合业务应用直接绑定某一个 API。
4. **【安全评估】把 Agent 当作独立机器身份管理。** 尤其是 Coding / Cyber Agent，应配置短期 Token、最小权限、工具白名单、沙箱、审计与 Human-in-the-loop。
5. **【研发试点】从 GitHub 六个方向选择 1—2 个 PoC。** Coding 团队优先 Orca / ECC；企业助手优先 QwenPaw；模型平台团队优先 llm-d；语音场景优先 speech-to-speech。
