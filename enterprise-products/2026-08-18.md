### 1. Atlassian｜客户数据贡献与 AI 数据使用新规则已正式生效

**优先级：P0**

**发生了什么**

Atlassian 官方确认，从 **2026-08-17** 起，开始依据各组织的数据贡献设置，使用符合条件的客户 metadata（元数据）和 in-app data（应用内数据）来改进面向所有客户的 Atlassian 产品和 AI 体验。

初始覆盖范围包括 Jira、Confluence、Jira Service Management，以及 Atlassian Platform 中的 Rovo、Home、Teams、Projects、Assets、Goals、Analytics、Administration 和部分 Teamwork Graph 连接器。

官方同时更新了 Atlassian Customer Agreement、AI Terms、Data Processing Addendum 和 Privacy Policy，这些条款均自 2026-08-17 起生效。

默认策略与套餐有关：

- Free / Standard：metadata 默认贡献且不可关闭，in-app data 默认开启但可关闭；
- Premium：metadata 默认贡献且不可关闭，in-app data 默认关闭；
- Enterprise：metadata 和 in-app data 均可由组织管理员按可用设置进行管理；
- 部分使用 CMK/BYOK、Government Cloud、Isolated Cloud、HIPAA 配置或政府客户的组织会被排除在数据贡献之外。

**客户影响**

重点影响：

- 使用 Jira / Confluence / JSM 的企业客户；
- 使用 Rovo、企业搜索或 AI Agent 的客户；
- 对数据训练、内容二次使用、隐私、数据驻留有严格要求的客户；
- 金融、医疗、政府、跨境和强审计行业客户；
- 正在进行 Atlassian Cloud 迁移或试用的客户。

这是数据治理和合同条款层面的变化，不是普通功能升级。

**CSM 建议**

- **建议立即主动联系**重点 Atlassian Cloud 客户，提醒管理员检查 Data contribution settings；
- 对 Standard / Premium 客户重点解释 metadata 的默认规则和可控边界，避免客户误以为所有数据都可以完全关闭；
- 对 Enterprise、CMK/BYOK、政府、医疗等客户，可作为“AI 数据治理与合规配置”专项回访话题；
- 对正在续费或扩容 Atlassian 的客户，应将数据贡献设置、AI 条款和组织治理能力纳入续费沟通。

**项目经理关注**

- 更新涉及 Atlassian / Rovo 的安全设计、数据流和合规说明；
- 检查项目需求或合同中是否存在“客户数据不用于跨客户产品优化/模型改进”等承诺；
- 对多组织客户需要逐个组织检查设置，不能只验证一个 tenant；
- 如涉及 Cloud Migration Trial，也应纳入数据贡献评估；
- 建议将数据贡献设置截图或配置结果纳入上线验收和运维文档。

**来源**

- 官方来源：[Atlassian - Data contribution FAQs](https://www.atlassian.com/trust/ai/data-contribution/faqs)
- 官方来源：[Atlassian - Data practices built for responsible AI](https://www.atlassian.com/trust/ai/data-contribution)

### 2. Salesforce｜员工用户 MFA 强制执行进入后续生产批次

**优先级：P0**

**发生了什么**

Salesforce 正在对员工用户分批实施技术层面的 MFA 强制执行。官方计划按实例 Release Group 分批推进：

- R2a：2026-08-10 ～ 2026-08-17；
- R2b：2026-08-10 ～ 2026-08-13；
- Japan & Korea：2026-09-01；
- 其他未列明实例：2026-09-03。

因此截至今天，R2a 批次已完成，尚未进入强制执行的客户主要集中在 9 月批次。

**客户影响**

重点影响：

- 仍存在仅用户名 + 密码登录员工账号的 Salesforce 客户；
- 使用 SSO / IdP，但未验证 Salesforce MFA 例外与信任链配置的客户；
- 测试账号、运维账号、共享账号或长期无人使用账号较多的客户；
- 正在实施 Salesforce、Agentforce 或 CRM 集成项目的客户。

**CSM 建议**

- **需要主动通知**尚未完成 MFA 检查的 Salesforce 客户；
- 将 MFA readiness 作为客户健康检查的一部分，重点确认生产实例所属 Release Group；
- 对使用 SSO 的客户不要简单认为“已有 SSO 就不受影响”，应确认当前身份认证方案是否满足 Salesforce 要求；
- 对 9 月批次客户，可安排管理员培训或上线前检查。

**项目经理关注**

- 核对客户生产实例属于哪个 Release Group；
- 对管理员、集成账号、自动化账号和人工登录账号分别验证认证方式；
- 如项目涉及 SSO，需要补充 MFA / IdP / 登录策略回归测试；
- 建议在 9 月 1 日或 9 月 3 日前完成生产环境登录演练和应急账号检查；
- 更新运维手册、账号开通 SOP 和上线检查表。

**来源**

- 官方来源：[Salesforce Help - Prepare for MFA Enforcement for All Employee Users](https://help.salesforce.com/s/articleView?id=000389313&language=en_US&type=1)
- 当前关键批次完成日期：2026-08-17
- 后续强制日期：2026-09-01 / 2026-09-03

### 3. WorkBuddy｜5.3.12～5.3.13 连续升级，重点改善企业模型治理与任务稳定性

**优先级：P1**

**发生了什么**

WorkBuddy 官方更新日志显示：

**5.3.13（2026-08-13）**

- 新增“灵感一键做同款”，支持快速套版复刻网页；
- 优化同时运行多个任务时的流畅度；
- 优化资料库上传体验；
- 修复子任务长期停留在准备中、WeData 图表不展示、网页搜索空链接等问题。

**5.3.12（2026-08-12）**

- 修复企业管理员调整模型白名单后，客户端仍显示旧自定义模型的问题；
- 修复 IMA 连接器偶发掉线、需要重新授权的问题；
- 修复本地助理内存快速增长导致白屏或崩溃；
- 修复本地助理重启后任务上下文丢失；
- 优化移动端连接电脑在弱网、休眠恢复后的同步和续聊稳定性。

**客户影响**

重点影响：

- 已部署 WorkBuddy Enterprise 或企业智能体的客户；
- 使用自定义模型白名单和企业模型治理的客户；
- 使用 IMA / 知识库连接器的客户；
- 使用本地助理、远程任务、多任务并行执行的客户；
- 正在进行 WorkBuddy PoC 或生产推广的客户。

**CSM 建议**

- 对正在使用企业模型白名单的客户，建议确认客户端版本并验证新策略是否及时生效；
- 对过去反馈 IMA 掉线、本地助理白屏、上下文丢失的客户，可主动回访并建议升级验证；
- 多任务流畅度改善适合作为 WorkBuddy 生产可用性回访话题；
- “灵感一键做同款”可用于设计、运营和内容团队的轻量 Demo，但不属于必须通知事项。

**项目经理关注**

- 企业版项目升级后重点测试：模型白名单同步、IMA 授权、长时间运行内存、多任务并行和任务恢复；
- 如果项目依赖自定义模型或企业管理员控制策略，建议将 5.3.12 以上版本作为新的兼容性基线；
- 如曾有本地助理崩溃或上下文恢复问题，应安排一次长任务回归测试。

**来源**

- 官方来源：[WorkBuddy 更新日志](https://www.workbuddy.cn/docs/workbuddy/Changelog)
- 5.3.13 发布日期：2026-08-13
- 5.3.12 发布日期：2026-08-12
