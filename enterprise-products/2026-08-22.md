### 1. Slack｜新增未来 AI 功能访问控制，并加强私有频道权限治理

**优先级：P1**

**发生了什么**

Slack 官方 2026 年 8 月更新页新增管理员治理能力：

- Workspace Primary Owner（Pro、Business+、Enterprise Select）以及 Org Primary Owner（Enterprise Grid、Enterprise+）可以决定**未来新发布的 Slack AI 功能是否自动开启**；
- Private Channel 的 Channel Manager 可以限制成员**分享或下载文件**，并限制**是否允许添加 Guest**；
- 同期还支持 Canvas 的 `Can comment` 权限，允许评论和表情互动但不能编辑内容。

**客户影响**

重点影响：

- 已经大规模使用 Slack AI、Slackbot、Enterprise Search 的企业；
- 对 AI 功能上线需要经过安全评估或 Change Management 的客户；
- 金融、研发、法务、人力等有敏感频道和文件下载限制需求的组织；
- 使用 Slack Connect、Guest、外部协作比较多的企业。

**CSM 建议**

- 建议主动联系已启用 Slack AI / Slackbot 的企业客户，确认“未来 AI 功能自动开启”策略是否符合内部治理要求；
- 对强合规客户，可将私有频道文件下载限制和 Guest 管理作为安全治理升级点；
- 适合作为 Business+ / Enterprise 客户的回访和管理员培训内容；
- 有条件的客户可安排一次管理员权限治理 Demo。

**项目经理关注**

- 如果项目方案默认“新 Slack AI 功能发布后自动可用”，需要改为以客户组织策略为准；
- 涉及私有频道文件同步、下载或 Guest 协作的自动化，需要重新确认权限边界；
- 更新管理员配置文档、安全设计和 UAT 用例；
- 如有自研应用依赖私有频道文件操作，应增加权限被限制后的异常处理测试。

**来源**

- 官方来源：https://slack.com/help/articles/115004846068-Slack-updates-and-changes
- 发布日期：2026-08（Slack 官方更新页未披露具体日；2026-08-22 检索确认）

### 2. Microsoft Graph｜文件容器支持批量 Upsert 列定义，消息分区重排 API 进入预览

**优先级：P1**

**发生了什么**

Microsoft Graph 2026 年 8 月更新中：

- **Files：** `fileStorageContainer` 新增 **Upsert columns** 方法，可一次创建或更新最多 20 个 `columnDefinition`，该能力已列入 GA；
- **Teamwork and communications / Messaging：** 预览新增 `reorder sections` 和 `reorder section items` 操作，可以给用户分区及分区内条目应用完整自定义排序。

**客户影响**

重点影响：

- 使用 Microsoft Graph 构建企业文档、文件容器、内容管理平台的客户；
- 自研 Microsoft 365 工作台、消息聚合、任务导航或定制侧边栏的客户；
- 使用 Graph 做企业集成和二次开发的 ISV / 项目团队。

文件列批量 Upsert 能降低多次 API 调用和幂等处理复杂度；Messaging 重排能力仍为 Preview，不建议未经隔离直接用于核心生产逻辑。

**CSM 建议**

- 对有 Microsoft 365 深度集成项目的客户，可主动介绍 Graph 的新文件容器能力；
- 对正在规划自定义消息导航、工作台或 Teams 扩展的客户，可将重排 API 作为后续 PoC 能力；
- Preview 功能不建议作为正式交付承诺，应明确试验性质。

**项目经理关注**

- 已有文件容器列管理逻辑可评估是否改用批量 Upsert，减少请求次数；
- 增加 API 版本和权限回归测试；
- Preview Messaging API 应与生产逻辑隔离，避免接口变化导致兼容性问题；
- 如有 SDK 封装层，建议更新 Graph API 能力清单与技术方案文档。

**来源**

- 官方来源：https://learn.microsoft.com/en-us/graph/whats-new-overview
- 发布日期：2026-08（Microsoft Graph 官方月度更新；页面于 2026-08 中旬更新）

### 3. Microsoft 365｜App Manifest v1.30 增加 Outlook Add-in 加解密能力声明

**优先级：P1**

**发生了什么**

Microsoft 365 App Manifest Schema 在 **2026 年 8 月**进入 **v1.30**。官方说明新增 Outlook Add-in 的 Encryption-Decryption 支持，通过新的 `headerName` 和 `sendMode` 属性描述加解密行为。

**客户影响**

重点影响：

- 开发或部署 Outlook Add-in 的企业；
- 有邮件加密、数据防泄漏、敏感信息保护需求的客户；
- 统一使用 Microsoft 365 App Manifest 管理 Teams / Outlook 扩展的项目。

**CSM 建议**

- 对邮件安全和合规需求强的客户，可将此能力作为 Outlook 扩展升级讨论点；
- 如果客户正在建设邮件安全插件或企业自研 Add-in，建议安排技术评估；
- 不建议把 schema 新能力直接等同于完整邮件安全解决方案，仍需结合 Purview、Exchange 和客户现有安全架构。

**项目经理关注**

- 检查项目是否仍固定在旧 manifest schema；
- 如需要新加解密能力，先在测试租户验证 `headerName` / `sendMode` 行为；
- 更新 manifest 校验、CI schema 校验和兼容性测试；
- 涉及老版本客户端时需要确认版本兼容范围。

**来源**

- 官方来源：https://learn.microsoft.com/en-us/microsoft-365/extensibility/schema/
- 发布日期：2026-08

## 四、CSM 重点关注

1. **Slack AI 管理策略值得主动回访。** 已经采购 Slack AI / Enterprise 的客户，应确认是否允许未来 AI 功能自动开启，避免功能上线速度快于企业安全审批流程。
2. **Slack 私有频道安全能力适合强合规客户。** 对研发、法务、金融、人力等敏感协作场景，可推荐文件下载限制和 Guest 管理能力。
3. **Microsoft 365 深度集成客户可安排开发者能力回顾。** Graph Upsert columns 和 App Manifest v1.30 都属于可以降低开发成本或拓展安全能力的新变化。
4. **Salesforce 客户继续推进 MFA 收口。** 日本/韩国以及其他剩余生产实例将在 9 月 1 日和 9 月 3 日进入强制阶段。
5. **Atlassian 客户不要拖延 JQL 迁移。** 9 月 10 日后 Jira Product Discovery interval date 的旧查询写法将停止工作。

## 五、项目经理重点关注

1. **Slack 项目增加管理员策略测试。** 特别检查 AI 自动启用、Private Channel 文件下载和 Guest 权限。

3. **Microsoft 365 App Manifest 做 schema 兼容性检查。** 如有 Outlook Add-in，评估 v1.30 的加解密属性是否进入后续迭代。
