### 1. Notion｜Developer Portal 进入工作区侧边栏，Workers/API 运维入口集中化

**优先级：P1**

**发生了什么**

Notion 于 **2026-08-19** 发布新的 Developer 区域。管理员和开发者现在可以直接从工作区侧边栏集中管理 **Workers、Connections、Personal Access Tokens**，并查看已部署 Workers 与每次运行日志。同时新增 developer bar，可快速复制 page、database、block、workspace、user 等对象 ID 或完整 API object。

**客户影响**

重点影响：

- 使用 Notion API、Webhook、Workers 的企业客户；
- 使用 Custom Agents + Workers 做自动化的团队；
- 需要排查 Worker 执行失败、权限、Token 和对象 ID 的开发团队；
- 需要统一开发者能力治理和运维可观测性的 Enterprise 客户。

这次变化不会直接破坏既有 API，但明显降低了开发和排障成本，尤其适合已有 Notion Agent / 自动化项目的客户。

**CSM 建议**

- 建议对使用 Workers、API 或 Custom Agents 的客户主动介绍新的 Developer 区域；
- 可作为一次“自动化运维可视化”回访话题，帮助客户检查 Worker 日志、连接和 Token 管理方式；
- 对准备做 Notion Agent / API PoC 的客户，可将该能力加入 Demo；
- 如客户此前因为 API 对象 ID 查找和日志排查复杂而降低使用意愿，适合重新推动试点。

**项目经理关注**

- 更新 Notion API / Workers 项目的管理员手册和排障 SOP；
- 将 Worker 日志入口纳入上线后的监控和故障排查流程；
- 检查 Personal Access Token 的存量管理方式，避免开发者个人 Token 无治理使用；
- 可在 UAT 中增加 Developer Portal 的权限和日志可见性验证。

**来源**

- 官方来源：https://www.notion.com/releases
- 发布日期：2026-08-19

### 2. Google Workspace｜Drive Inventory Reporting 增强外部分享与 DLP 风险识别

**优先级：P1**

**发生了什么**

Google Workspace 于 **2026-08-17** 发布 Drive Inventory Reporting 的外部分享洞察增强。管理员在 BigQuery 导出的 Drive Inventory 中可以更清晰地识别：直接外部权限、群组成员带来的外部访问、公开链接、服务账号以及“发布到 Web”的文件，并可结合已有 **DLP metadata** 优先定位高风险数据。

该能力默认关闭，需要管理员在 Drive inventory report 设置中启用 **External sharing calculations**。Google 同时提醒：大型 Google Group 较多的组织启用后可能增加处理时间并影响报告交付时间。

**客户影响**

重点影响：

- Google Workspace Enterprise Standard / Plus 客户；
- 有外部协作、第三方共享、数据防泄漏要求的企业；
- 金融、医疗、政府、研发等需要定期做数据暴露审计的客户；
- 已使用 BigQuery、DLP、Drive Inventory 做安全治理的客户。

**CSM 建议**

- 建议向强合规或外部协作频繁的客户主动推荐；
- 可将“Drive 外部共享风险盘点”设计成客户健康检查或安全专项服务；
- 对已有 DLP 能力但缺少全局外部共享视角的客户，适合安排一次管理员 Demo；
- 对 Enterprise 客户可进一步讨论审计、治理、培训或安全方案升级机会。

**项目经理关注**

- 如果项目包含 Google Drive 数据治理，应评估是否启用 External sharing calculations；
- 在正式启用前验证 BigQuery 报告处理时间，尤其是大型群组较多的租户；
- 更新安全设计文档，将外部分享洞察与 DLP 联动纳入审计流程；
- 如项目有定时报表或数据管道，需要评估 schema 新字段与处理耗时变化。

**来源**

- 官方来源：https://workspaceupdates.googleblog.com/2026/08/enhanced-external-sharing-insights-now-available-in-Drive-Inventory-Reporting.html
- 发布日期：2026-08-17
- Rollout：自 2026-08-14 起渐进发布，最长约 15 天

### 3. WorkBuddy｜5.3.14 聚焦自动化调度、长期记忆与多 Agent 稳定性

**优先级：P2**

**发生了什么**

WorkBuddy 于 **2026-08-17** 发布 5.3.14。该版本虽以修复和体验优化为主，但包含多项对企业自动化实际运行有意义的改进：

- 优化自动化任务高峰期调度，减少集中触发和误判错过执行；
- 优化长期记忆加载与本地助理变量恢复；
- 修复多个任务同时提问时回复内容串话；
- 修复子 Agent 沙箱任务可能永久等待；
- 修复腾讯文档授权入口、文件分享和 WeData 图表等问题；
- 优化并行任务切换卡顿和历史任务白屏。

**客户影响**

重点影响：

- 已用 WorkBuddy 执行定时自动化任务的客户；
- 使用多任务、多 Agent、长期记忆的客户；
- 集成腾讯文档、WeData 等企业工具的客户；
- 将 WorkBuddy 用于正式办公和生产场景的团队。

**CSM 建议**

- 对已经用于生产办公自动化的客户建议主动提醒升级；
- 如果客户此前反馈“任务漏触发、串话、上下文恢复异常”，可安排升级后回访；
- 暂不建议把该版本作为大范围营销主题，但适合作为稳定性改善和客户问题闭环的沟通点；
- 对正在做多 Agent PoC 的客户，可将 5.3.14 作为推荐验证版本。

**项目经理关注**

- 升级后重点回归自动化任务调度、多任务并行、长期记忆和子 Agent 沙箱；
- 如果项目依赖腾讯文档授权、文件分享或 WeData 图表，建议补充对应回归测试；
- 检查历史版本是否存在针对这些问题的临时绕行方案，升级后可评估是否移除；
- 生产环境升级应保留自动化任务执行记录，用于前后版本对比。

**来源**

- 官方来源：https://www.workbuddy.cn/docs/workbuddy/Changelog
- 发布日期：2026-08-17
- 版本：5.3.14
